### **Resumo Geral**

O vídeo apresenta um sistema RAG (Retrieval-Augmented Generation) mais avançado chamado **Agentic RAG**, que utiliza **n8n** e **Supabase** para processar **dados vetorizados** e **dados tabulares**, combinando automação, agentes inteligentes e maior capacidade de raciocínio para oferecer respostas mais precisas. A grande vantagem do modelo agentic é que o agente pode decidir entre diferentes fontes de dados (ex: SQL, PDFs, vetores) e adaptar suas ações de acordo com o tipo de pergunta feita.

---

### **Tópicos com Exemplos e Explicações**

1. **O que é RAG tradicional**

   * Recupera contexto de uma base de dados (geralmente vetorial) e gera uma resposta.
   * Exemplo: Pergunta “qual a missão da empresa X?” → agente busca isso no banco vetorial.

2. **Como funciona a vetorização**

   * Documentos são divididos em “chunks” (trechos), vetorizados via modelo de embeddings e armazenados em um banco vetorial como o PGVector do Supabase.

3. **Limitações do RAG tradicional**

   * Só trabalha com os chunks mais próximos — pode ignorar contexto importante de um documento inteiro.
   * Exemplo: Se um PDF tem 20 páginas e apenas 4 chunks são retornados, a resposta será parcial.

4. **O que é Agentic RAG**

   * O agente **toma decisões inteligentes**:

     * Escolhe entre banco vetorial ou consulta SQL.
     * Entende esquemas de dados tabulares.
     * Lê conteúdos completos se necessário.
   * Exemplo: Se a pergunta é "qual semana teve mais vendas?", o agente pode usar SQL ao invés de vetores.

5. **Diferença prática entre vetores e SQL**

   * Vetores não são bons para lógica matemática (ex: somas, médias).
   * SQL é mais adequado para dados estruturados como planilhas.
   * Exemplo:

     * Pergunta: "Qual semana teve mais vendas?"
     * SQL retorna a semana correta.
     * Vetores poderiam retornar uma semana com alta venda apenas dentro do *chunk* lido.

6. **Exemplo com dados tabulares (CSV ou Google Sheets)**

   * Usando Supabase, dados são inseridos como linhas em uma tabela.
   * O agente consegue fazer queries SQL reais.
   * Exemplo: calcular “valor médio de clientes únicos por semana” → resposta exata com `AVG()` SQL.

7. **Fail-safe inteligente**

   * Se uma query falha (ex: valor nulo), o agente tenta novamente ou usa `get file contents` como plano B para ler todo o conteúdo e gerar a resposta correta.

8. **Resumo de documentos com Agentic RAG**

   * Limitação: se o chunk limit estiver em 4, a resposta é parcial.
   * Solução: usar `get file contents` para obter o documento completo.
   * Exemplo: comando “resuma todos os projetos” → o agente busca todos os IDs dos documentos e recupera os arquivos completos para gerar um resumo preciso.

9. **Interface no n8n com Supabase**

   * Três tabelas principais:

     * `documents`: dados vetorizados.
     * `document_rows`: dados tabulares (como planilhas).
     * `document_metadata`: títulos, IDs, esquema de colunas.
   * O template pré-pronto no vídeo configura tudo com três nós no n8n.

10. **Exemplos práticos finais**

    * Consulta vetorial: “Qual o conteúdo do projeto Green Grass sobre outreach?”
      → Resposta contextualizada e precisa.
    * Consulta lógica: “Qual projeto tem custo de 50 mil?”
      → Resposta correta: Mountaintop.
    * Resumo completo: “Resuma todos os nossos projetos”
      → Agente usa `get file contents` para ler todos os arquivos antes de responder.

---

### **Conclusão**

* O Agentic RAG é uma evolução natural do RAG tradicional, unindo raciocínio contextual com ações estratégicas como consultas SQL e leitura completa de arquivos.
* Utilizar o n8n com Supabase permite montar fluxos prontos para aplicar este conceito de forma visual e automatizada.
